# Relar: the first experiment

Relar compiles a closed set of first-party Python sources ahead of time through LLVM. The compiler and runtime are independent Rust implementations. The first deliverable is a useful example program, an executable that needs no Python installation, and a reproducible comparison with the same source running on CPython.

## Language contract

Types are requirements. Named functions declare parameter and return types; local types are inferred or explicitly declared. Assignments, calls, returns, and container writes must satisfy those types. A contradiction is a compilation error. Values entering from input or, eventually, foreign code are checked before a specialized representation is used. A failed check is a language error, never an unchecked memory reinterpretation.

The initial types are `int`, `bool`, `str`, `None`, and `list[int]`. Integer arithmetic keeps arbitrary precision, floor division, and Python's remainder convention. Booleans are a distinct static type in this subset: using one in an integer slot requires an explicit conversion. Integer object identity and general object introspection are not exposed. Lists have identity, shared mutation, negative indexing, and checked bounds. An alias cannot change the element type of a list.

The initial control flow is annotated functions, assignments, conditionals, loops, and direct calls. The prototype starts with one source module and a fixed set of builtins. Its exact accepted syntax is documented alongside the implementation. Unsupported syntax is rejected, including unsupported syntax in otherwise unreachable branches.

Compilation fixes function identities and signatures. The language does not initially include arbitrary imports, `eval`, `exec`, namespace mutation, monkey patching, reflective attribute access, user-defined classes, metaclasses, decorators, generators, coroutines, or `Any`. These are scope decisions, not invitations to silently approximate Python behavior. Classes and additional protocols can be added with explicit rules for field layout, typed mutation, dispatch, and reentrancy.

We retain ordinary value semantics where supported: arbitrary-precision integers, left-to-right expression evaluation, short-circuit control flow, alias-visible list changes, and bounds errors. Catchable builtin exceptions now preserve cleanup on normal and exceptional exits; full traceback objects remain later work.

## Compiler

The pipeline is Ruff's cached parser and ty's semantic analysis, a deliberately small Relar contract checker, a typed intermediate representation, ownership lowering, textual LLVM IR, and LLVM optimization and native linking. We pin the Ruff/ty component crates together and use the system LLVM 18 Clang driver to compile the generated IR. Clang does not compile the Python source or generated C.

We embed ty's Salsa database, vendored type definitions, semantic checking, and diagnostic rendering. Relar consumes the same parsed Ruff AST after ty succeeds. The second checker implements only the accepted type language: a general Python type checker's inferred types, stubs, `cast`, or user-defined narrowing functions would not by themselves establish the runtime proofs needed by the backend. Exact runtime types, effects, and storage decisions remain explicit in Relar. Suppression comments cannot waive Relar's runtime type contract.

The IR records resolved calls, expression types, variable slots, control flow, and supported runtime operations. The backend only accepts checked IR. Integer operations ordinarily use a checked machine-integer fast path and an already-compiled arbitrary-precision fallback. A fallback continues the operation at that point; it does not restart earlier side effects.

Eager comprehensions lower to compiler-private typed helper functions using the existing loops, containers, and cleanup scopes. The caller evaluates the leftmost iterable in its own scope and supplies the referenced enclosing local values as borrowed arguments. This snapshot is valid because expressions and callees cannot rebind caller slots in the closed subset; mutable field reads stay inside the helper and aliases keep sharing their objects. Every comprehension target is local throughout its inner scope, and nested comprehensions get separate helpers. Helpers participate in the final call graph and effect analysis, including those generated while checking inactive module guards. No callable object, captured heap environment, or runtime callback ABI is introduced.

Comprehension filters become ordered control flow. Dictionary leaves acquire their key before evaluating the value, then insert through the existing typed mapping operation. The result and iterator roots use ordinary function/scope cleanup on success and failure. This follows the supported [Python comprehension evaluation and scope rules](https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries) while keeping generators and assignment expressions outside the subset.

Exact class fields and interned container shapes survive into native lowering. Each class and escaping tuple has a concrete LLVM structure with one aligned word per field. Generated field accesses use direct loads and stores; a shared static descriptor supplies the runtime's destruction information. Pointer fields remain LLVM pointers, and integer fields retain their canonical tagged representation. These layouts preserve identity and shared mutation without a runtime tag on each field.

Optionals use one nullable word throughout calls, locals, fields, and containers. Zero denotes absence; present integers and pointers keep their payload representation, while `False` and `True` use words one and two. Wrapping and narrowing move an owner rather than allocating or destroying a wrapper. Borrowed inputs are acquired before the result can outlive them. The compiler proves a payload present before decoding it; the encoding does not change Python's integer or boolean values.

A conservative interval pass tracks immutable integer values held in local slots, accounting for reassignment, branches, loop backedges, and short-circuit evaluation. Facts describe each expression at its evaluation point after IR rewrites; heap reads and user-call results remain unknown. Analysis overflow discards affected bounds. Small-operand proofs allow direct comparisons; direct arithmetic additionally requires a small-result proof. Arithmetic and tagging shifts receive `nsw` only when their signed results are proved representable. A possibly zero divisor retains the checked path. A native `range` cursor requires small captured arguments, a nonzero step of known sign, and bounds covering the initial cursor and its final increment; rebinding the visible loop target does not change that cursor. Unknown facts retain ordinary checked lowering.

A separate whole-function proof can establish that a nonparameter integer local never owns a `BigInt`. It checks every assignment, range binding, and ownership move before omitting old-value and exit ownership checks. Parameters, missing facts, and unknown replacements disqualify a slot; move dependencies propagate that disqualification until stable.

A proved nonnegative small index can cross the runtime ABI as an exact decoded native index. The runtime still checks the container's current length on every access, including after calls or mutation through aliases. Negative and arbitrary-precision indices retain the general normalization and error path. No cached-length or unchecked-bounds assumption is introduced.

Eligible non-escaping tuple locals become separate owned component slots before LLVM emission. This includes calls to single-return tuple producers when every use is a fixed projection or length query. Arguments and elements are evaluated once, in order, and all new components are captured before replacing old ones. Tuples that escape or are used as whole values retain the boxed ABI.

The IR also records protected bodies, fixed exception handlers, finally blocks, raise operations, and cleanup scopes for compiler-owned roots. Exceptional edges release already-produced expression temporaries before entering cleanup scopes or a handler. Function propagation releases owned locals; a caught error preserves ordinary local state. Finally handles a saved completion reason and can replace it, releasing any displaced return value or exception. Handler and finally analysis cannot inherit facts that depend on a fallible operation having completed.

A conservative effect analysis over the final IR identifies functions that cannot raise a language exception. It includes argument evaluation, constructors, callees, handlers, and finally bodies; uncertain operations retain their checks. Fixed-field accesses cannot fail after the checker has established the field layout and complete initialization, so they do not require a pending-error query. Container bounds checks, mapping iteration errors, input/output failures, and explicit raises retain propagation and cleanup. These proofs rely on closed bindings and layouts, and must be revisited before introducing callbacks, dynamic attributes, or foreign implementations.

The initial native calling convention uses concrete typed values and borrowed arguments. Returned reference-bearing values are owned. Each expression and local has an explicit lifetime; assignment publishes the new value before releasing the old value. The caller keeps inputs rooted until a call completes. Operator and call inputs can borrow direct locals, and parameter bindings that never change can share the caller's root. This proof depends on expressions being unable to replace caller slots: closures, globals, assignment expressions, and exposed frame addresses are absent. List-element reads generally remain owned because later evaluation can remove the element. Unchanged bindings do not imply immutable or unaliased objects.

A two-operand integer comparison may borrow a direct local integer-list element at a proved nonnegative small index. Both complete operand trees must belong to a narrow nonmutating whitelist: integer literals, integer locals, integer arithmetic, and direct-local integer-list reads. Calls, mutators, fields, and chained comparisons retain ordinary ownership. Only the direct comparison operands use the borrowed getter; nested arithmetic keeps its existing ownership lowering. The local roots the container until the comparison consumes the handle, and no intervening evaluation can remove its element. A separate same-local `items[i] = items[j]` fusion requires both indices to be simple nonnegative small literals or locals. Those index reads cannot fail or mutate; the runtime checks and acquires the source before checking and replacing the destination, including self-copy.

## Runtime

The runtime provides integers, strings, fixed fields, typed containers, input, output, and checked errors. Heap allocations do not move. Reference counting provides predictable ownership; the supported heap type graphs cannot form reference cycles. Introducing recursive containers, closures, or cyclic object graphs requires a cycle-collection design before claiming those graphs are reclaimable.

Language errors use explicit Result values inside Rust and a pending-error channel at the native ABI. Generated code checks every fallible call before interpreting its result. This keeps Rust unwinding out of the language exception mechanism. Pending and dynamically active errors own separate references; handlers and exceptional finally blocks save and restore the active error so bare raise works across calls. Exception objects store only a builtin category and immutable message, without cyclic traceback/frame references. Uncaught errors return a process status after generated-code cleanup. Allocation failure and invalid internal ABI use remain terminal.

The successful-path query reads a separate thread-local presence byte without touching the pending owner's destructor or borrow state. The two helpers that replace or transfer that owner also update the byte before releasing displaced references. The owning cells and their thread-exit cleanup remain intact; the mirror depends on the runtime's absence of reentrant callbacks between those updates.

Integer-list reads use a direct failure result: raw zero cannot be a canonical integer, including numeric zero, whose tagged word is one. Integer-list writes return a separate success byte. Generated code branches on those results before decoding or acquiring them, through the same temporary-release and propagation path as a pending-error query. Generic container results retain the query because zero can represent a successful boolean, `None`, or absent optional. Every ordinary fallible call enters with pending state clear; these private ABI changes require rebuilding the compiler and runtime together.

Error installation is kept in cold, non-inlined helpers, and generated exceptional branches carry cold weights. This keeps allocation, pending-owner replacement, and error cleanup out of hot accessor bodies so LLVM can inline their successful paths. The hints never remove the failure edge or change handler selection.

Sealed UTF-8 file handles are a leaf in the heap type graph. Their boxed stream state keeps existing object layouts compact, and aliases share closure and buffering state. Explicit close detaches the stream before flushing and closing, so a failed close still leaves a closed handle. Final reference release performs best-effort cleanup without setting pending errors or calling user code; this preserves the compiler's infallible ownership-cleanup contract. A builtin-file `with` lowers to an independent hidden root and the existing try/finally completion machinery, retaining all return, error, and loop-transfer cleanup rules.

Selected standard-library names are compiler-recognized bindings, not imported Python modules. The current surface includes the file annotation, the file-operation exception category, and a shared mutable argument list. Only programs using process arguments capture C `argc`/`argv`; the first access decodes strict UTF-8 and publishes the shared list only after complete success. Generated entry cleanup releases its runtime root on normal and exceptional exits. General modules, codecs, protocols, and surrogateescaped strings remain separate compatibility decisions.

Integer representation is canonical: every value from `-2**62` through `2**62 - 1` uses a tagged machine word, and values outside that range use a shared `BigInt` allocation. Results return to the tagged form whenever they fit, so a value-range proof also establishes representation. Future extension adapters must normalize incoming integers before exposing them to generated code.

Container storage owns its elements behind opaque handles. Scoped `UnsafeCell` access relies on single-threaded, nonreentrant runtime operations: mutable access is exclusive, and neither storage references nor resizable-buffer addresses may escape. General reads acquire independent owned values; the compiler-only comparison getter returns a borrowed integer handle under the contract above. Writes acquire replacements and drop displaced owners only after storage access ends. Aliased handles observe sequential mutations and continue sharing allocations. These rules depend on the closed ABI's absence of callbacks and finalizers, and must be preserved before introducing either or sharing handles across threads.

Ordinary signed decimal input parses directly into a tagged integer; separators and larger values retain the checked arbitrary-precision path. Short strings keep their UTF-8 bytes inside the reference-counted allocation using the already-pinned `compact_str` crate. Longer strings own a separate buffer. These representations remain private to the runtime.

Exact string-concatenation trees can join their fragments in one capacity-checked operation. Leaves still evaluate from left to right, and computed string values keep independent roots across later mutation and exceptions. Literals borrow immutable UTF-8 spans. An exact `str(int)` leaf converts at its original evaluation point: tagged integers use 20 bytes of caller scratch, while larger integers produce one owned formatted string. After checking the total capacity, the runtime copies each fragment directly into the result and publishes its length once. Each descriptor array and integer buffer has unique function-entry storage, reused across loop iterations without stack growth; nested concatenations cannot overwrite an earlier fragment. Other conversions keep their existing behavior. Removing intermediate allocations preserves the runtime's terminal allocation-failure contract.

A discarded sealed-file `write` result uses a success-byte ABI that omits the unused Unicode character count. A direct concatenation also reuses the ordered fragment staging and builds its complete text without a temporary reference-counted wrapper. Assembly finishes before checking file state, then the existing single write runs; receiver and fragment roots survive the status check. Receiver and text evaluation, shared file state, and checked error cleanup keep their existing order. A write whose result is used still returns its character count.

Fixed records have one allocation containing a reference count, a pointer to their static descriptor, and their field payload. All fields start as zero, and destruction skips zero owning words, so a constructor or tuple expression can fail after initializing any prefix without leaking earlier values or reading an uninitialized owner. The checker prevents partial records from escaping. Field replacement acquires the new value, publishes it, then releases the displaced value; reads acquire their result before releasing the record root.

General sequences store a vector of words and one element representation kind. Dictionaries specialize their hash keys for integers or strings and store value words under one value kind; sets store keys without dummy values. Bounds errors, negative indexing, insertion order, iterator mutation checks, and reference ownership remain unchanged. These are private compiler/runtime representations, so the compiler and runtime must be rebuilt together.

Tagged integers print through an `itoa` stack buffer; strings, booleans, and `None` write their encoded bytes directly. Larger integers use arbitrary-precision formatting. The bounded output buffer flushes each terminal line and before input, fatal errors, or normal process return.

Rust helps protect the runtime implementation, but it does not prove emitted LLVM IR safe. Unsafe handle operations stay in a narrow runtime boundary with documented contracts. Differential tests, ownership tests, and sanitizer runs must cover generated code as well as runtime code.

The scriptc failures that motivated this project were failures of lifetime and mutation reasoning across callbacks. Before adding callbacks or finalizers, runtime operations and IR instructions must distinguish operations that can reenter user code. Borrowed container storage cannot survive such an operation; callbacks must remain rooted while running; collection iteration must define how mutation is observed. Dropping a reference can itself become a reentrant operation.

## Room for extensions

The initial implementation does not emulate CPython or load extension modules. Future extension support targets selected extensions rebuilt against our headers; unchanged CPython wheels are not an initial compatibility promise.

Keep the internal native calling convention separate from any future boxed C-facing convention. Keep reference ownership and object identity explicit. Keep allocation, ownership, and errors behind runtime interfaces while allowing compiler-proved native field access. These choices allow later checked adapters and callable wrappers without putting C-API calls in every optimized operation today.

We do not commit native containers to CPython's internal layouts. A later adapter must preserve shared mutation and identity, or make conversion explicit. A mutable foreign list cannot become a trusted `list[int]` merely because its current elements passed a one-time check. The eventual boundary must mediate writes, use checked reads, or make an explicit independent copy.

## Prototype and evidence

The first program is a weighted-grid route planner with an ordinary Python implementation of a binary heap and Dijkstra's algorithm. It exercises function calls, loops, arithmetic, shared mutable lists, bounds checks, and data-dependent control flow. CPython executes exactly the same `.py` file and receives identical input.

Correctness gates precede timing: full output comparisons, multiple grid sizes and seeds, an independent small-grid oracle, arithmetic edge cases beyond native integer range, negative indexing, mutation aliases, evaluation order, and rejection of unsupported or ill-typed programs.

Measurements retain raw alternating paired samples, input and source hashes, compiler and interpreter versions, host and CPU information, executable hashes, and compilation time. Report the timing boundary explicitly. End-to-end process timing includes startup and output for both implementations; compilation is measured separately. No performance multiplier is promised in advance.
