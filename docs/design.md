# Imre: the first experiment

Imre compiles a closed set of typed Python sources ahead of time through LLVM, including selected unchanged pure-Python libraries. The compiler and runtime are independent Rust implementations. The first deliverable is a useful example program, an executable that needs no Python installation, and a reproducible comparison with the same source running on CPython.

## Language contract

Types are requirements. Named functions declare parameter and return types; local types are inferred or explicitly declared. Assignments, calls, returns, and container writes must satisfy those types. A contradiction is a compilation error. Values entering from input or, eventually, foreign code are checked before a specialized representation is used. A failed check is a language error, never an unchecked memory reinterpretation.

The initial types are `int`, `bool`, `str`, `None`, and `list[int]`. Integer arithmetic keeps arbitrary precision, floor division, and Python's remainder convention. Booleans are a distinct static type in this subset: using one in an integer slot requires an explicit conversion. Integer object identity and general object introspection are not exposed. Lists have identity, shared mutation, negative indexing, and checked bounds. An alias cannot change the element type of a list.

The initial control flow is annotated functions, assignments, conditionals, loops, and direct calls. The prototype starts with one source module and a fixed set of builtins. Its exact accepted syntax is documented alongside the implementation. Unsupported syntax is rejected, including unsupported syntax in otherwise unreachable branches.

Compilation fixes function identities and signatures. The language does not initially include arbitrary imports, `eval`, `exec`, namespace mutation, monkey patching, reflective attribute access, user-defined classes, metaclasses, decorators, generators, coroutines, or `Any`. These are scope decisions, not invitations to silently approximate Python behavior. Classes and additional protocols can be added with explicit rules for field layout, typed mutation, dispatch, and reentrancy.

We retain ordinary value semantics where supported: arbitrary-precision integers, left-to-right expression evaluation, short-circuit control flow, alias-visible list changes, and bounds errors. Catchable builtin exceptions now preserve cleanup on normal and exceptional exits; full traceback objects remain later work.

## Compiler

The pipeline is Ruff's cached parser and ty's semantic analysis, a deliberately small Imre contract checker, a typed intermediate representation, ownership lowering, textual LLVM IR, and LLVM optimization and native linking. We pin the Ruff/ty component crates together and use Clang 18 on Linux or Apple Clang on macOS to compile the generated IR. Clang does not compile the Python source or generated C.

We embed ty's Salsa database, vendored type definitions, semantic checking, and diagnostic rendering. Imre consumes the same parsed Ruff AST, retaining ty's semantic errors except for checks explicitly owned by the closed language contract. Operand, assignment, argument, and return compatibility are enforced by Imre's exact checker; ty's open Python flow model can retain `None` after a successful float literal pattern even though the captured value is definitely present. These four compatibility diagnostic categories are deferred to the exact checker, which validates every statement, including dead code and unused functions. Other ty errors remain fatal.

Known out-of-bounds indices and zero slice steps remain checked runtime errors so programs can catch them or leave them in an unselected expression. The exact checker still enforces index types and fixed tuple bounds: a general Python type checker's inferred types, stubs, `cast`, or user-defined narrowing functions would not by themselves establish the runtime proofs needed by the backend. Exact runtime types, effects, and storage decisions remain explicit in Imre. Suppression comments cannot waive Imre's runtime type contract.

The IR records resolved calls, expression types, variable slots, control flow, and supported runtime operations. The backend only accepts checked IR. Integer operations ordinarily use a checked machine-integer fast path and an already-compiled arbitrary-precision fallback. A fallback continues the operation at that point; it does not restart earlier side effects.

For repeated builds in one process, `imre_compiler::IncrementalCompiler` retains ty's diagnostic database across revisions. A file that imports one function can reuse its diagnostic result when that function's implementation changes or its module gains another export. Salsa tracks the semantic queries and source spans that contributed to the result. The loader resolves the current graph on every call. A different module root, file identity or failed import lookup replaces the database. Every revision runs Imre's whole-program preflight and lowering, so edits to default values and exception behavior reach the generated caller. Run `imre check --watch path/to/main.py` to check each saved revision. The watcher tracks the source bytes, file identities, and failed import lookups the loader saw, including on an unsuccessful check. It retains native directory registrations while the watch paths stay the same. For a multiwrite save it waits for 10 ms of quiet, with a three-second cap on a burst.

Lowering can also ask ty for the scalar type of a first append or whether an `assert_never` argument has type `Never`. When a revision uses either query, the compiler retains its diagnostics-disabled database. On the next matching graph it updates changed sources after preflight, then lowers the ASTs from that database so each expression and semantic query refer to the same revision. Successful lowering releases the database when it uses neither query. If an error interrupts lowering before the first hint, a previously retained database survives for the repair.

Missing function annotations use a finite discovery pass over the closed source graph. Scalar defaults and direct calls supply concrete parameter types; a body whose inputs are known supplies its return type. The ordinary checker performs this discovery, including calls inside comprehensions, but its temporary IR and ownership state are discarded. Each unknown signature slot is filled once. A second complete check uses immutable concrete signatures and enforces every annotation, caller, return, inactive body, initialization dependency, and recursion restriction. Unknown types never reach the executable IR, and inference adds no runtime dispatch or object representation.

Imported modules have typed native slots for fixed value bindings. Direct initialization assignments publish one owned value per slot; imported aliases and re-exports resolve to that same slot. The loader schedules each initializer once in dependency and source order. Before emitting code, a transitive read/call analysis rejects initialization that reaches a later global or definition, including through constructors, methods, and comprehension helpers. Global reads acquire owners, and process cleanup releases every initialized slot even after initialization fails. Shared containers remain mutable, so global reads do not establish immutable heap contents or cached-length proofs.

Exact callable values add a fixed signature and target, optionally owning a bound instance receiver. They may cross local, parameter, and return boundaries, but cannot enter imported globals, class fields, containers, or tuples. Noncapturing lambdas become checked private functions with contextual parameter types; they do not allocate captured-local environments. These restrictions preserve the acyclic heap contract. Indirect calls acquire the callable before argument evaluation, retain each argument in source order, and preserve the ordinary owned-result and checked-error conventions. Direct calls retain their keyword/default behavior; indirect calls require full positional arity.

The bounded `str | bytes` union uses one alignment bit of an owned string/bytes pointer to identify its member; zero remains available for a nullable union. Storage descriptors retain and release the masked pointer without allocating a wrapper. `isinstance` checks establish local member facts, which become explicit owned projections in IR. Mutations and flow joins invalidate those facts as needed; arbitrary unions, runtime class objects, and covariant mutable-container conversions remain unsupported.

Eager comprehensions without assignment expressions lower to compiler-private typed helper functions using the existing loops, containers, and cleanup scopes. The caller evaluates the leftmost iterable in its own scope and supplies the referenced enclosing local values through the native calling convention. This snapshot is valid because these comprehension expressions and callees cannot rebind caller slots; mutable field reads stay inside the helper and aliases keep sharing their objects. Every comprehension target is local throughout its inner scope, and nested comprehensions get separate helpers. Helpers participate in the final call graph and effect analysis, including those generated while checking inactive module guards. No callable object, captured heap environment, or runtime callback ABI is introduced.

Comprehension filters become ordered control flow. Dictionary leaves acquire their key before evaluating the value, then insert through the existing typed mapping operation. The result and iterator roots use ordinary function/scope cleanup on success and failure. This follows the supported [Python comprehension evaluation and scope rules](https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries).

Immediately consumed generator expressions and builtin iterator adapters share typed pull-based lowering. Preparation captures sources and performs iterator acquisition at the Python evaluation point; a separate step computes the next item or exhaustion. Nested generators keep their clause state and private targets in local slots. Their bodies read enclosing bindings when pulled, rather than capturing a snapshot, and assignment expressions update the actual enclosing slots. The consumer can stop without executing another step.

`zip` combines these steps in left-to-right order and emits strict-length probes only on exhaustion. `any` and `all` use ordinary truth tests and exit at the first decisive item. Reversed lists keep a descending cursor over live storage, while reversed strings use a UTF-8 cursor between code-point boundaries. Roots for sources, current items, and partially assembled tuples use the existing cleanup machinery. These operations expose native control flow to LLVM without adding a public iterator representation, closure ABI, or general generator-function state machine.

Generalized `map` and `filter` use the same immediate pull states. Preparation roots the callback and source; each successful pull owns its element before invoking user code. Map publishes the callback's result, while filter truth-tests that result and preserves the original element. Neither keeps a runtime storage borrow across callback execution. Mutation and exception analyses must account for indirect calls before proving readonly buffers, rooted borrows, integer bounds, or infallible operations. Unknown effects keep the ordinary checked, owned path. The closed call graph also rejects cycles through callable dispatch.

Destructured private tuple results expose their components to scalar replacement. When a tuple can transitively own a file, zip and enumerate instead retain CPython's cached-result ownership: a unique cache is reused, while a shared cache stays unchanged and a fresh result is allocated. Zip replaces fields immediately after each successful pull. This preserves observable implicit file closure without forcing allocation for tuples whose final release has no language-visible effect.

Immediate integer consumers can remove private intermediates before LLVM sees them. `list(map(int, text))` converts directly from Unicode characters into canonical integer words, preserving left-to-right validation and the first invalid character's diagnostic. A fixed tuple consumed by `sum`, including a `divmod` result, can use scalar component slots. An integer comprehension consumed immediately by `sum` accumulates directly while retaining the comprehension's eager body, filter, scope, and exception order. A narrowly proved readonly reverse-slice comprehension can traverse the original rooted list without copying its slice. Escaping results and shapes that fail a rewrite's ownership or effect proof keep their ordinary representation.

Integer-list sums use a bounded native subtotal where possible and an exact arbitrary-precision fallback. Ordinary `sum(items, start)` evaluates `start` before reading the list, so mutations through aliases remain visible. A consumed slice instead captures its subtotal before evaluating the later `start` expression, preserving the original slice snapshot. These operations never reinterpret an annotation as evidence that an integer fits in a machine word.

Assignment expressions lower to an explicit binding operation whose result and
local storage hold separate owners. Comprehensions containing these writes run
inline with private target slots and cleanup scopes; they do not capture a
snapshot of the enclosing binding. Exported bindings survive both normal and
exceptional cleanup. Flow joins intersect definite assignments and optional
facts across all possible expression exits. Ordinary assignment checks the RHS
before its receiver and index; a private checker supplies target type context
without publishing speculative writes or helper functions.

The current interval and tuple-projection passes assume expressions do not
replace local slots. Functions containing assignment expressions retain generic
checked integer operations and aggregate tuple storage until those passes model
expression writes. Functions without these writes retain their existing proofs.

Exact class fields and interned container shapes survive into native lowering. Each class and escaping tuple has a concrete LLVM structure with one aligned word per field. Generated field accesses use direct loads and stores; a shared static descriptor supplies the runtime's destruction information. Pointer fields remain LLVM pointers, and integer fields retain their canonical tagged representation. These layouts preserve identity and shared mutation without a runtime tag on each field.

Optionals use one nullable word throughout calls, locals, fields, and containers. Zero denotes absence; present integers and pointers keep their payload representation, while `False` and `True` use words one and two. For these payloads, wrapping and narrowing move an owner rather than allocating or destroying a wrapper. Present optional floats instead own a small immutable binary64 allocation, preserving all float bit patterns within the one-word nullable ABI. Borrowed inputs are acquired before the result can outlive them. The compiler proves a payload present before decoding it; the encoding does not change Python's integer or boolean values.

A conservative interval pass tracks immutable integer values held in local slots, accounting for reassignment, branches, loop backedges, and short-circuit evaluation. Facts describe each expression at its evaluation point after IR rewrites; general heap reads and user-call results remain unknown. Analysis overflow discards affected bounds. Small-operand proofs allow direct comparisons; direct arithmetic additionally requires a small-result proof. Arithmetic and tagging shifts receive `nsw` only when their signed results are proved representable. A possibly zero divisor retains the checked path. A native `range` cursor requires small captured arguments, a nonzero step of known sign, and bounds covering the initial cursor and its final increment; rebinding the visible loop target does not change that cursor. Unknown facts retain ordinary checked lowering.

A separate closed-call-graph analysis can prove integer-list element bounds from constructors, slices, and every direct caller. Unknown callers, mutation, or uncertain effects discard those facts. An ordinary bounded-element read still checks its index before asserting the value's canonical representation and interval to LLVM. Nonnegative division by a positive constant can then use a comparison when the numerator is proved smaller than twice that constant; wider and signed cases retain their existing exact operations.

Canonical reductions have an additional loop-entry length guard. A zero subtotal, at most one bounded addition per iteration, a stable readonly source, and a monotonically advancing cursor establish a safe native accumulator budget. The original loop remains the fallback. Within the guarded version, exact source/cursor reads before the unique cursor advance are also proved in bounds. They use an infallible borrowed accessor; reads after the advance, in the loop's else suite, from another source, or at another index retain checks. Hidden writes, cleanup, early continue paths, callbacks, and nested loops must all satisfy the proof rather than inheriting it from interval widening.

The checked accumulator proof selects native arithmetic directly, without adding redundant LLVM assumptions that obscure its reduction recurrence. LLVM chooses further loop transformations through its ordinary legality and profitability checks; generated code does not promise that a reduction can be vectorized.

Conditional expressions retain explicit branch control flow through lowering. The checker narrows optional locals separately in each arm and joins only identical concrete types or their supported optional form. LLVM receives a typed phi with one transferred result owner from either predecessor. Branch-local temporaries never enter the other arm's cleanup path. Integer range analysis evaluates the condition before refining each reachable arm, then joins their resulting intervals; effect and ownership traversals inspect both arms.

List and string slices use three nullable integer words for their bounds and stride. Their receiver and bounds remain rooted through source-order evaluation, and the runtime reads current list storage only after those expressions finish. Arbitrary-precision bounds are normalized against the current length before allocation; copied list slots acquire the same concrete ownership representation as the source. String operations use Unicode scalar positions over immutable UTF-8 storage. Internal string iterators retain the source and advance a byte cursor between code-point boundaries, yielding independent string owners without repeated scans from the beginning.

Bytes have a distinct immutable `Rc<Vec<u8>>` representation and concrete ownership descriptor (tag 8); no byte payload is interpreted as UTF-8 until explicit decoding. Byte indexes and iterator results are canonical immediate integers. The shared slice normalizer clips arbitrary-precision bounds before copying selected bytes. Exact byte-key dictionaries and sets use monomorphized hash tables, and nullable bytes use the existing zero-word niche. Binary streams share descriptor ownership, buffering, and context cleanup with text streams while preserving their separate access and decoding contracts.


A separate whole-function proof can establish that a nonparameter integer local never owns a `BigInt`. It checks every assignment, range binding, and ownership move before omitting old-value and exit ownership checks. Parameters, missing facts, and unknown replacements disqualify a slot; move dependencies propagate that disqualification until stable.

A narrower assignment-time proof can omit old-value cleanup when the RHS first reads that exact local as a canonical small integer and cannot replace it during later evaluation. This applies only after the RHS succeeds; exceptional cleanup and unknown or arbitrary-precision replacements retain ownership checks.

A proved nonnegative small index can cross the runtime ABI as an exact decoded native index. The runtime checks the container's current length unless the separate canonical reduction proof above establishes that exact access is in bounds. Negative and arbitrary-precision indices retain the general normalization and error path.

Eligible tuple locals become separate owned component slots before LLVM emission. Arguments and elements are evaluated once, in order, and all new components are captured before replacing old ones. Fixed projections and length queries use those slots directly, including for inlined single-return tuple producers. A read-only dictionary or set lookup can build a stack key from the saved components of a tuple literal. If one dictionary insertion can publish the key at most once per construction, that insertion builds the owned tuple. Other escaping uses keep the boxed representation.

The IR also records protected bodies, fixed exception handlers, finally blocks, raise operations, and cleanup scopes for compiler-owned roots. Exceptional edges release already-produced expression temporaries before entering cleanup scopes or a handler. Function propagation releases owned locals; a caught error preserves ordinary local state. Finally handles a saved completion reason and can replace it, releasing any displaced return value or exception. Handler and finally analysis cannot inherit facts that depend on a fallible operation having completed.

A conservative effect analysis over the final IR identifies functions that cannot raise a language exception. It includes callee and argument evaluation, constructors, handlers, and finally bodies. An indirect call is infallible only when every constructed target of its exact signature is infallible; unknown or empty target sets retain their checks. Fixed-field accesses cannot fail after the checker has established the field layout and complete initialization, so they do not require a pending-error query. Container bounds checks, mapping iteration errors, input/output failures, and explicit raises retain propagation and cleanup. These proofs rely on closed bindings and layouts, and must be revisited before introducing dynamic attributes or foreign implementations.

Checked builtin contracts centralize operation fallibility and the heap guarantees used by effect, borrow, and list analyses. Preserving existing owners is weaker than preserving list contents and storage: append, reserve, and sort can keep owners alive while moving their slots. Neither guarantee implies purity; a path operation can perform I/O, and a defaultdict lookup can insert a mapping entry. Contracts exclude argument evaluation, which each analysis accounts for separately. Every builtin requires an explicit classification; generic native-call error checks live alongside these contracts.

Debug and test builds verify the IR after lowering and each specialization pass. The verifier checks type and local identities, storage layouts, call bindings, and the operand shapes and recorded bounds required by specialized list operations. An invalid module reports the first failing stage before another pass consumes it. Release builds can enable the same checks with the compiler's `verify-ir` feature, which CI uses for native differential tests. Verification checks structural consistency; aliasing, dominance, and the truth of inferred ranges remain the responsibility of their analyses.

Native calls pass concrete typed values and return owned reference-bearing results. The caller evaluates arguments in source order, then transfers one owner of each parameter that can transitively contain a file. Rebinding such a parameter can close its previous value inside the callee. A constructor keeps its own argument owners until `__init__` returns. Returning frames with observable final releases clear their owned slots in reverse slot order. Other stable parameters borrow caller roots, and rebound parameters acquire an owner on entry. Each assignment publishes its new value before releasing the old value. Earlier operands keep separate owners across assignments that could replace their source. Closures, global rebinding, and exposed frame addresses remain absent. List-element reads generally remain owned because later evaluation can remove the element. Unchanged bindings do not imply immutable or unaliased objects.

A two-operand integer comparison may borrow a direct local integer-list element at a proved nonnegative small index. Both complete operand trees must belong to a narrow nonmutating whitelist: integer literals, integer locals, integer arithmetic, and direct-local integer-list reads. Calls, mutators, fields, and chained comparisons retain ordinary ownership. Only the direct comparison operands use the borrowed getter; nested arithmetic keeps its existing ownership lowering. The local roots the container until the comparison consumes the handle, and no intervening evaluation can remove its element. A separate same-local `items[i] = items[j]` fusion requires both indices to be simple nonnegative small literals or locals. Those index reads cannot fail or mutate; the runtime checks and acquires the source before checking and replacing the destination, including self-copy.

## Runtime

The runtime provides integers, strings, fixed fields, typed containers, input, output, and checked errors. Heap allocations do not move. Reference counting provides predictable ownership; the supported heap type graphs cannot form reference cycles. Introducing recursive containers, closures, or cyclic object graphs requires a cycle-collection design before claiming those graphs are reclaimable.

The explicit `imre.json.decode` boundary validates external data against a compile-time record, list, or string-keyed dictionary schema. Decoded records require structural initializers: exact parameter-to-field assignments, scalar missing-field defaults, and the proved fresh-empty-list idiom. The decoder builds ordinary concrete storage directly, preserving canonical integer representation and acyclic ownership. String visitors copy borrowed JSON text into its final owned representation without a temporary string allocation. Partial records, lists, and dictionaries remain private and release initialized owners on failure. Known record fields and dictionary keys reject duplicates, while unknown record fields retain the established skip behavior.

`imre.json.encode` walks those concrete layouts directly, with scalar and optional roots also allowed. Record field order and dictionary insertion order determine output order. It invokes no user callbacks or constructors, so an encode-only record does not need a structural initializer. Checked indentation and Unicode-escaping options produce Python-compatible output for the supported finite values. Both boundaries enforce a depth limit and expose no dynamic JSON value type. A separate checked CPython module supplies the same source API; its dynamic parse tree is confined to that compatibility implementation.

`imre.toml.decode` shares the compiler-proved record schemas, defaults, ownership descriptors, and concrete storage with typed JSON. Its roots are records or string-keyed dictionaries. The pinned maintained `toml` parser validates complete TOML 1.1 documents into a private temporary tree whose borrowed scalar tokens preserve TOML categories and whose tables retain source order. Conversion constructs only the requested typed values; it does not pass through JSON or erase dates into synthetic maps. Integer tokens normalize through the canonical tagged/BigInt representation without an integer-width limit. Float fields require TOML floats and retain binary64 infinities and NaNs; booleans remain distinct from both numeric types. Every partial list, mapping, or record owns its initialized values and reclaims them on conversion failure.

TOML parsing validates ignored fields, including duplicate declarations and datetime syntax. A separate complete-tree check enforces at most 64 table/array containers along any path, counting the document table, and CPython's representable calendar range. Datetime values are accepted only in ignored data until an explicit native datetime representation exists. Missing optional fields still require constructor defaults, and list factories produce fresh owners through the shared default machinery. The CPython shim uses TOML 1.1 `tomllib` on Python 3.15+ and requires `tomli>=2.4` on earlier versions; its decimal integer conversion guard remains configurable by the application, while native decoding has no digit cap. The temporary tree is discarded after conversion. The executable links the native parser and needs no Python runtime.

Language errors use explicit Result values inside Rust and a pending-error channel at the native ABI. Generated code checks every fallible call before interpreting its result. This keeps Rust unwinding out of the language exception mechanism. Pending and dynamically active errors own separate references; handlers and exceptional finally blocks save and restore the active error so bare raise works across calls. Exception objects store a builtin category, immutable message, optional explicit cause, and suppression flag. A sealed process-error payload additionally owns the original argument list and captured strings, retaining dynamic command formatting without arbitrary exception attributes. Causes can only be attached to freshly constructed exceptions and their attributes cannot be written, so chains remain acyclic; uniquely owned tails are destroyed iteratively to avoid stack growth. Tracebacks, frames, and implicit context remain absent. Uncaught errors print explicit chains and return a process status after generated-code cleanup. Allocation failure may remain terminal; invalid internal ABI use is terminal.

The successful-path query reads a separate thread-local presence byte without touching the pending owner's destructor or borrow state. The two helpers that replace or transfer that owner also update the byte before releasing displaced references. The owning cells and their thread-exit cleanup remain intact; the mirror depends on the runtime's absence of reentrant callbacks between those updates.

Integer-list reads use a direct failure result: raw zero cannot be a canonical integer, including numeric zero, whose tagged word is one. Integer-list writes return a separate 32-bit success flag. Generated code branches on those results before decoding or acquiring them, through the same temporary-release and propagation path as a pending-error query. Generic container results retain the query because zero can represent a successful boolean, `None`, or absent optional. Every ordinary fallible call enters with pending state clear; these private ABI changes require rebuilding the compiler and runtime together.

Error installation is kept in cold, non-inlined helpers, and generated exceptional branches carry cold weights. This keeps allocation, pending-owner replacement, and error cleanup out of hot accessor bodies so LLVM can inline their successful paths. The hints never remove the failure edge or change handler selection.

Sealed UTF-8 file handles are a leaf in the heap type graph. Their boxed stream state keeps existing object layouts compact, and aliases share closure and buffering state. Explicit close detaches the stream before flushing and closing, so a failed close still leaves a closed handle. Final reference release performs best-effort cleanup without setting pending errors or calling user code; this preserves the compiler's infallible ownership-cleanup contract. A builtin-file `with` lowers to an independent hidden root and the existing try/finally completion machinery, retaining all return, error, and loop-transfer cleanup rules.

Selected standard-library names are compiler-recognized bindings, not imported Python modules. The current surface includes the file annotation, the file-operation exception category, and a shared mutable argument list. Only programs using process arguments capture C `argc`/`argv`; the first access decodes strict UTF-8 and publishes the shared list only after complete success. Generated entry cleanup releases its runtime root on normal and exceptional exits. General modules, codecs, protocols, and surrogateescaped strings remain separate compatibility decisions.

Native `pathlib.Path` values are immutable UTF-8 POSIX paths in the existing reference-counted object representation. Their operations resolve statically, including value equality and representations inside records and containers; no `os.PathLike` dispatch or Python module executes. Lexical normalization preserves `..` and the POSIX double-slash anchor. Text methods reuse the file runtime's decoding, newline, error, and close behavior. Directory consumers use private iterator state: `iterdir` snapshots names at method evaluation, while `glob` snapshots on the first pull, following Python 3.14. The scan closes before yielding; each yielded path has its own owner. Exhaustion, early exits, and errors reclaim the remaining snapshot through the ordinary iterator cleanup machinery.

Path resolution walks components against the filesystem, resolving symlinks before applying parent traversal. Per-call symlink state distinguishes cycles from repeated and arbitrarily long acyclic chains. Strict resolution preserves operating-system errors; non-strict resolution normalizes the unresolved suffix. Both operations return the existing immutable path representation, without introducing a filesystem protocol or new object layout.

Synchronous subprocess calls form another sealed Unix boundary. The checker fixes capture and encoding modes, stages supplied arguments in source order, and lowers to one fallible native call. The runtime prepares the executable arguments and optional replacement environment only after that evaluation completes. It inherits stdin, captures and drains both output pipes, closes unrelated descriptors in the child, and waits before decoding UTF-8 and checking status. A completed result owns its original argument list and immutable captures; field getters acquire independent owners, and equality retains Python object identity. Read-only fields and string-only argument lists keep this addition acyclic. Environment snapshots and process-error fields have concrete checked representations; no Python module, arbitrary mapping protocol, or user callback participates in the launch path.

Timed subprocess calls pass integer and float seconds through separate native entry points. The runtime keeps the original value for `TimeoutExpired` and starts a monotonic deadline after launch. A nonblocking poll loop drains both streams without waiting for descendants that inherit a pipe. Expiry snapshots undecoded bytes, kills and reaps the direct child, and closes captures. Catch bindings and `isinstance` narrowing expose `bytes | None` captures. The compiler gives `.timeout` an exact numeric layout when all deadline sites agree on its kind.

The [value struct contract](subset.md#immutable-value-structs) uses the annotated class and
decorator form established by [PEP 557](https://peps.python.org/pep-0557/).
[Brett Cannon’s record prototype](https://discuss.python.org/t/struct-in-python/62777/2)
explored dedicated declaration syntax; Imre keeps existing Python syntax and opts into
different *identity and storage* rules through the decorator. [PEP 585](https://peps.python.org/pep-0585/#objects-created-with-bare-types-and-parameterized-types-are-exactly-the-same)
explains why ordinary CPython erases the element argument when creating a list.
The compatibility module therefore implements value behavior, while the Imre compiler uses
the checked element type to select native row storage.

Repeating a singleton stores one immutable record and a count. A different slot
needs only an entry in a touched 64-slot block: the bitmap identifies changed
positions, and its set bits index consecutive scalar payloads in that block.
Writing back the default bits removes the entry; deleting the last one frees the
table. The list handle stays the same. An escaped value owns its snapshot.
Legacy consumers can request a boxed pointer array; unchanged slots reuse the
same immutable record, and mutation invalidates the array.

The runtime considers packing when inserting a new exception. It packs when over
one quarter of the slots differ, or when over 1/64 differ and at least half of
the blocks contain an exception. It counts distinct changed slots, including a
newly appended slot, against the resulting length. The [density benchmark](../benchmarks/results/2026-10-25-struct-edit-density.md)
compares clustered and scattered edits. A successful conversion takes O(n) work
and stays dense thereafter; a failed reservation can still fall back to a sparse
write. Replacing an existing exception or reading the list never triggers packing.

A proven read-only scan hoists its view of dense or uniform storage. For sparse
lists it caches a run in the loop frame: an untouched run broadcasts one row,
and adjacent edits within a block use consecutive rows. Neither needs per-row
boxes. Indexed reads can look up their block directly; slices map touched
positions through the normalized stride without building an array of length n.

Ordinary floats use LLVM `double` values and double fields; homogeneous containers carry their raw binary64 bits under one shared descriptor. They need no reference ownership. LLVM receives no fast-math permission. Mixed arithmetic explicitly checks integer conversion, while mixed comparisons compare an exact truncated-float integer and fractional sign. Integer true division scales the arbitrary-precision ratio and rounds once to nearest-even, including subnormals, instead of converting both operands independently. Optional floats own nullable `Rc<f64>` payloads so signed zero and every NaN bit pattern remain distinct from None.

Float literals come from Ruff's AST. String conversion normalizes Python's decimal grammar before Rust's correctly rounded parser, using the existing pinned ICU character categories for Unicode digits. Ruff supplies nonfinite formatting; finite shortest digits use the already-pinned Ryu implementation because Ruff's current Rust-based finite formatter differs from Python at decimal ties. A small notation adaptation adds Python's exponent threshold, sign, and minimum width. Explicit exact-type checking prevents Python typing's permitted int-to-float assignment widening from silently changing stored values.

Integer representation is canonical: every value from `-2**62` through `2**62 - 1` uses a tagged machine word, and values outside that range use a shared `BigInt` allocation. Results return to the tagged form whenever they fit, so a value-range proof also establishes representation. Future extension adapters must normalize incoming integers before exposing them to generated code.

Container storage owns its elements behind opaque handles. Scoped `UnsafeCell` access relies on single-threaded, nonreentrant runtime operations: mutable access is exclusive, and neither storage references nor resizable-buffer addresses may escape. General reads acquire independent owned values; compiler-only borrowed getters rely on the lifetime and value proofs above. Writes acquire replacements and drop displaced owners only after storage access ends. Aliased handles observe sequential mutations and continue sharing allocations. User callbacks run only after storage access ends. The absence of user finalizers keeps ownership cleanup nonreentrant; adding finalizers or sharing handles across threads requires preserving these rules.

Integer lists can reuse two empty vector buffers and two empty allocation headers per thread. Buffer retention is capped at 512 KiB; headers retain another 80 bytes on the supported 64-bit layout. Every element owner is released before storage enters either cache. A header is reusable only after its last strong owner is consumed and no weak references remain, so live aliases keep their identity and contents. Cache borrowing failure and thread-local teardown fall back to ordinary destruction.

Ordinary signed decimal input parses directly into a tagged integer; separators and larger values retain the checked arbitrary-precision path. Short strings keep their UTF-8 bytes inside the reference-counted allocation using the already-pinned `compact_str` crate. Longer strings own a separate buffer. These representations remain private to the runtime.

Integer text conversion normalizes Unicode 16 decimal digits before the checked parser. A small decimal-block table pins this behavior to CPython 3.14 independently of newer ICU data. Invalid-literal diagnostics reuse Ruff's quoting, correct the known ICU/Unicode 16 printability difference, and apply Python's 200-character repr limit. This changes neither the existing float parser nor other exception quoting.

Exact string-concatenation trees can join their fragments in one capacity-checked operation. Leaves still evaluate from left to right, and computed string values keep independent roots across later mutation and exceptions. Literals borrow immutable UTF-8 spans. An exact `str(int)` leaf converts at its original evaluation point: tagged integers use 20 bytes of caller scratch, while larger integers produce one owned formatted string. After checking the total capacity, the runtime copies each fragment directly into the result and publishes its length once. Each descriptor array and integer buffer has unique function-entry storage, reused across loop iterations without stack growth; nested concatenations cannot overwrite an earlier fragment. Other conversions keep their existing behavior. Removing intermediate allocations preserves the runtime's terminal allocation-failure contract.

F-strings lower to these same ordered string-concatenation operations. The checker preserves adjacent ordinary and formatted literal parts and validates each part under its own raw-prefix rules. Exact string fields already have their final representation. Scalar fields use sealed builtins. If a fixed record declares `__str__`, the checker resolves a bare field or `!s` to a direct call with one receiver. The compiler tracks that call’s mutation and exception effects like any other method. A `!r` field uses the record’s repr. Each field converts before the next expression evaluates.

Direct calls preserve source evaluation order separately from parameter order. The checker binds named and positional arguments against one fixed signature, applying exact contextual types and filling omitted parameters from checked scalar literal defaults. Call IR stores the receiver and supplied expressions in evaluation order plus a permutation into the native parameter order. LLVM retains each evaluated value before evaluating the next and permutes only references to those values at the call. Tuple-producer scalarization follows the same staging and permutation. Defaults have immutable scalar values whose identity is unobservable in the subset; materializing them at omitted calls preserves the value semantics without introducing module initialization effects or mutable shared defaults. The runtime ABI and ownership rules remain unchanged.

A discarded sealed-file `write` result uses a success-byte ABI that omits the unused Unicode character count. A direct concatenation also reuses the ordered fragment staging and builds its complete text without a temporary reference-counted wrapper. Assembly finishes before checking file state, then the existing single write runs; receiver and fragment roots survive the status check. Receiver and text evaluation, shared file state, and checked error cleanup keep their existing order. A write whose result is used still returns its character count.

Fixed records have one allocation containing a reference count, a pointer to their static descriptor, and their field payload. All fields start as zero, and destruction skips zero owning words, so a constructor or tuple expression can fail after initializing any prefix without leaking earlier values or reading an uninitialized owner. The checker prevents partial records from escaping. Field replacement acquires the new value, publishes it, then releases the displaced value; reads acquire their result before releasing the record root.

General sequences store one element representation kind and up to three words inline, spilling to a heap buffer when needed. Dictionaries specialize their hash keys for integers, strings, bytes, or immutable fixed tuples and store value words under one value kind; sets store keys without dummy values. Tuple keys use their fixed field descriptors to hash and compare immutable values recursively, including nullable fields. They retain their ordinary owners, and mutable payloads cannot enter a key. Ordered scalar tuple shapes use the same descriptors for lexicographic comparison and stable sorting; optional fields and floats are excluded from ordering. Bounds errors, negative indexing, insertion order, iterator mutation checks, and reference ownership remain unchanged. These are private compiler/runtime representations, so the compiler and runtime must be rebuilt together.

Native text methods operate on borrowed UTF-8 inputs and publish owned results. Splitting and stripping use Python's whitespace definition; searches translate byte offsets into Unicode scalar indices. The bounded URL unquote operation decodes percent escapes with UTF-8 replacement without a Python module or general URL object model. Direct string slices with a unit stride copy one contiguous byte range after normalization; full slices may retain the original immutable owner. Static string literals have separate program-lifetime roots, while each evaluated use still acquires its own owner. Those roots are released on normal and exceptional entry exits, so pooling does not change the alias or consuming-concatenation rules.

Tagged integers print through an `itoa` stack buffer; strings, booleans, and `None` write their encoded bytes directly. Larger integers use arbitrary-precision formatting. The bounded output buffer flushes each terminal line and before input, fatal errors, or normal process return.

Rust helps protect the runtime implementation, but it does not prove emitted LLVM IR safe. Unsafe handle operations stay in a narrow runtime boundary with documented contracts. Differential tests, ownership tests, and sanitizer runs must cover generated code as well as runtime code.

The scriptc failures that motivated this project were failures of lifetime and mutation reasoning across callbacks. Runtime operations and IR instructions must distinguish calls that can execute user code. Borrowed container storage cannot survive such an operation; callbacks remain rooted while running, and collection iteration retains its live mutation rules. User finalizers remain unsupported: adding them would make dropping a reference another potentially reentrant operation.

## Room for extensions

Imre can link [native modules rebuilt for its extension ABI](extensions.md). A module uses a supported subset of `Python.h`, exports its usual `PyInit_*` entry point, and ships typed signatures with its native archive in a platform wheel. The signatures let the compiler check calls. The runtime also checks returned values and writes to shared typed lists.

Keep the internal native calling convention separate from any future boxed C-facing convention. Keep reference ownership and object identity explicit. Keep allocation, ownership, and errors behind runtime interfaces while allowing compiler-proved native field access. These choices allow later checked adapters and callable wrappers without putting C-API calls in every optimized operation today.

We do not commit native containers to CPython's internal layouts. A later adapter must preserve shared mutation and identity, or make conversion explicit. A mutable foreign list cannot become a trusted `list[int]` merely because its current elements passed a one-time check. The eventual boundary must mediate writes, use checked reads, or make an explicit independent copy.

## Prototype and evidence

The first program is a weighted-grid route planner with an ordinary Python implementation of a binary heap and Dijkstra's algorithm. It exercises function calls, loops, arithmetic, shared mutable lists, bounds checks, and data-dependent control flow. CPython executes exactly the same `.py` file and receives identical input.

Correctness gates precede timing: full output comparisons, multiple grid sizes and seeds, an independent small-grid oracle, arithmetic edge cases beyond native integer range, negative indexing, mutation aliases, evaluation order, and rejection of unsupported or ill-typed programs.

Measurements retain raw alternating paired samples, input and source hashes, compiler and interpreter versions, host and CPU information, executable hashes, and compilation time. Report the timing boundary explicitly. End-to-end process timing includes startup and output for both implementations; compilation is measured separately. No performance multiplier is promised in advance.
