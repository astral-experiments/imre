# Partial JSON activation design (not active)

The existing staged `stdlib/json.jsonl` has 216 original occurrences. Its IDs, occurrences and historical raw outcomes must be preserved. Four staged doctest source fields disagree with the frozen canonical registration source, so byte-identical staging and unconditional canonical source anchoring cannot both hold; that discrepancy is a separate activation blocker documented in `doctest-source-attribution.json`. It includes 34 tool timeouts, two recursion timeouts, raw failures/errors/skips, and inactive `paired` flags that have no authority. A `finite` raw-control cohort requires a matching completed stock/native inventory; `stock-only` requires the absent native originals to be `not_run`. Neither contract can encode real timeout/window observations without lying about them. The existing inactive-family staged model preserves them, but cannot activate a strict subset.

A proposed partial-family activation would put only fully controlled JSON receipts in a distinct `verified/stdlib/json.jsonl` shard, digest-bind both that verified shard and the unchanged original staged shard, and require exact source/platform/revision/ID/occurrence membership in the staged originals. Only the verified shard would enter the validated-receipt and pair totals. Every staged ID and occurrence must be anchored to the frozen canonical inventory or immutable pinned inventory. Staged observations would be counted separately and explicitly labeled unverified, with their outcomes not checked by the renderer; staged claims and flags could never activate them. The unchanged staged shard and original captures retain the historical timeout observations. The existing raw-control finite validator would still require every selected cohort's exact stock/native inventory, positive/negative graph, matched build identities, withdrawal evidence, and raw results.

This design is blocked on the independently owned generic stock-source archive/file byte-anchoring fix. JSON must restack on that merged fix and pass digest-rebound source, launcher/cohort, staged-to-finite/paired, native-revision, and malformed-capture negatives before any activation or presentation regeneration. No generic source-binding rule is implemented here.
