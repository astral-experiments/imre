# Partial JSON activation design (not active)

The existing staged `stdlib/json.jsonl` has 216 original occurrences and must remain byte-identical. It includes 34 tool timeouts, two recursion timeouts, raw failures/errors/skips, and inactive `paired` flags that have no authority. A `finite` raw-control cohort requires a matching completed stock/native inventory; `stock-only` requires the absent native originals to be `not_run`. Neither contract can encode real timeout/window observations without lying about them. The existing inactive-family staged model preserves them, but cannot activate a strict subset.

A proposed partial-family activation would put only fully controlled JSON receipts in a distinct `verified/stdlib/json.jsonl` shard, digest-bind both that verified shard and the unchanged original staged shard, and require exact source/platform/revision/ID/occurrence membership in the staged originals. Only the verified shard would enter the validated-receipt and pair totals. Staged observations would be counted and displayed separately as unverified raw observations, including their actual timeout labels; staged flags could never activate them. The existing raw-control finite validator would still require every selected cohort's exact stock/native inventory, positive/negative graph, matched build identities, withdrawal evidence, and raw results.

This design is blocked on the independently owned generic stock-source archive/file byte-anchoring fix. JSON must restack on that merged fix and pass digest-rebound source, launcher/cohort, staged-to-finite/paired, native-revision, and malformed-capture negatives before any activation or presentation regeneration. No generic source-binding rule is implemented here.
