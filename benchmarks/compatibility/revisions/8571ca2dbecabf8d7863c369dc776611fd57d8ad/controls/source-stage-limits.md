The direct-and-withdraw-v1 control rejects successful traced Linux open, openat, and openat2 operations on Python source, bytecode, ZIP or wheel payloads and fd payload aliases; it rejects every successful creat conservatively. It resolves relative directory descriptors using the shared trace parser. The saved test tree, launcher and original-source archive are withdrawn, and the saved process must not attempt another exec or probe CPython/libpython.

These traces do not establish adversarial confinement. They do not show reads from descriptors inherited before tracing, all possible memory mappings or IPC, kernel or filesystem behavior outside the traced calls, or eliminate symlink and other TOCTOU races. The origin/main ref used for offline source-stage ancestry checks is assumed to have been fetched from the configured public origin. Reviewed immutable public stage and activation commits remain the authority boundary.

A later data-only activation must pin `source_stage.commit`, the fixed manifest locator, its Git blob ID and SHA-256. The source commit must be a strict ancestor of the activation commit and reachable from the public-origin main ref. The adapter reads the manifest only through Git at that commit; a mutable working-tree copy is never authority. Each activation file set must equal the manifest's source/evidence set plus its new receipt. The manifest binds the original sparse stage, exact binding, strict mode, probe, collection/control sources and artifact digests. Existing historical activations do not use this authority check.
