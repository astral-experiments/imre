# uv-extra-03: unsupported original uv wrapper route

**Decision:** Imre does not support this original wrapper route. The [archived survey](https://github.com/astral-experiments/imre/blob/880648b620f57905a495eb51fbb4600755ee0c54/benchmarks/compatibility/historical-scripts/archived-survey-7724.tsv#L37) and [join](https://github.com/astral-experiments/imre/blob/880648b620f57905a495eb51fbb4600755ee0c54/benchmarks/compatibility/historical-scripts/join.jsonl#L36) record `uv-extra-03` with reported stock exit 0 and this argv:

```text
/opt/codex/runtimes/codex-primary-runtime/dependencies/python/bin/uv run --active --frozen --python /tmp/uvdisc/sdk-stock/python/bin/python3.14 --script /tmp/uvdisc/dirhash-locked/project/crates/uv-extract/test_vectors/dirhash.py vectors/0 vectors/1 vectors/2 vectors/3 vectors/4 vectors/1/a
```

At uv commit `24688aaca1e7fd104437a0909d5db3afdc7dcdb0`, the [entry](https://github.com/astral-sh/uv/blob/24688aaca1e7fd104437a0909d5db3afdc7dcdb0/crates/uv-extract/test_vectors/dirhash.py#L3) has SHA-256 `98282a35062dc25a8601719121e4a6bafba9e0056afe87d6b503a8342cd7acd7`; the [lock](https://github.com/astral-sh/uv/blob/24688aaca1e7fd104437a0909d5db3afdc7dcdb0/crates/uv-extract/test_vectors/dirhash.py.lock#L14) has SHA-256 `c1dacf19ac6e5264e2d20a45c6106a21eb8aca6ea7d41e5370818439c041b865`. The PEP 723 script requires `blake3>=1.0.9` and sets `no-build=true`. Its lock lists 26 binary wheels and zero pure wheels. The Linux x86_64 wheel is `blake3-1.0.9-cp314-cp314-manylinux_2_17_x86_64.manylinux2014_x86_64.whl`, SHA-256 `f65d77eb05331495485048f6804f53885b192b998acb7e6fe1487d941bf08435`.

uv's [InterpreterInfo::query](https://github.com/astral-sh/uv/blob/24688aaca1e7fd104437a0909d5db3afdc7dcdb0/crates/uv-python-interpreter/src/interpreter.rs#L1189) spawns the selected executable with `-I -B -c` and imports a temporary [query module](https://github.com/astral-sh/uv/blob/24688aaca1e7fd104437a0909d5db3afdc7dcdb0/crates/uv-python-interpreter/python/get_interpreter_info.py#L902) to inspect implementation, `sys.executable`, and installation schemes. [RunCommand::as_command](https://github.com/astral-sh/uv/blob/24688aaca1e7fd104437a0909d5db3afdc7dcdb0/crates/uv-project-commands/src/run.rs#L1688) then executes the reported interpreter with the script FILE. Imre does not promise that full interpreter/environment protocol or the CPython C ABI. Accepting pure wheel tags alone cannot satisfy this dependency; Imre must not claim the `cp314` ABI.

An alternative `imre build ...` followed by executing the image would require an independently supported BLAKE3 extension/provider or an explicit script rewrite. That alternative is outside the original cohort. Keep the denominator at 84, archived reported stock successes at 72, and credit for this route at 0. This is a source-derived compatibility decision, not a frozen-959 observation or a new receipt.
